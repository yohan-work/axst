## 왜 있는가

교육 결정권자 330명 조사에서 97%가 AI 교육이 필요하다고 답했지만 **82%는 교육 후 현업에서 활용하지 못한다.** 같은 조사에서 —

> 역량 진단이 필요하다고 느끼지만 방법을 모른다는 조직이 **51.5%**
> 진단 결과를 실제로 교육 설계에 반영한 조직은 **3.6%**

부족한 것은 문항이 아니라 **점수를 처방으로 번역하는 층**이다. 직무별 교육 설계의 성공률은 18%인데, 역량 진단 후 수준별 설계는 32%로 뛴다. 진단은 효과가 증명된 유일한 레버인데 대부분의 조직이 실행하지 못한다.

이 레포는 그 층을 만든다. 문항 뱅크만이 아니라 **채점 → 플래그 → 처방 → 스폰서 합의문**까지가 한 묶음이다.

출처: [AI 교육을 받고도 82%는 현업에서 쓰지 않습니다](https://blog.bloomworld.ai/why-ai-training-doesnt-stick/) (Bloom, 2026-09-15)

## 무엇이 다른가

시중 시험은 *"프롬프트 엔지니어링에 대한 설명으로 옳은 것"*, *"다음 중 Claude 모델이 아닌 것은"* 같은 **툴 상식**을 묻는다. 모델명과 기능명은 6개월이면 바뀌고, 그걸 아는 것과 업무에 쓰는 것 사이에 상관이 거의 없다.

**이 진단은 그런 문항을 금지한다.** 허용 유형은 상황 판단형(SJT) · 산출물 비평형 · 최선–최악형 셋뿐이다.

평가 축도 다르다. 시장의 진단 제품들이 공통으로 빠뜨린 것 — **"무엇을 AI에게 맡길 것인가"** — 를 1축으로 올렸다.

| | 위임 판단 | 워크플로우 재설계 | 조직 리포트 | 처방 연결 |
|---|:---:|:---:|:---:|:---:|
| 시장 진단 제품 일반 | ❌ | ❌ | 일부 | 부분 |
| **본 진단** | ✅ 1축 | ✅ 1축 | ✅ | ✅ 사전 합의문 |

축 정의와 배정 결정트리는 [docs/01-axes.md](docs/01-axes.md), 출제 규칙은 [docs/03-item-writing-rules.md](docs/03-item-writing-rules.md).

## 진단 구성

| 항목 | 값 |
|---|---|
| 응시 시간 | **35분** (안내·자기보고 2분 + 객관식 20분 + 주관식 13분) |
| 문항 | 객관식 20 + 주관식 2 (뱅크 24문항, 예비 4문항) |
| 평가 축 | 위임 판단력 · 작업 설계 · 검증/신뢰 조정 · 워크플로우 재설계 · 리스크/거버넌스 |
| 축별 배분 | 4 / 4 / 4 / 4 / 4 |
| 배점 | 객관식 60 + 주관식 40 = **100** |
| 응시 대상 | 전사 공통 1종 (주관식만 직무별 페르소나 6종 중 선택) |
| 개인 산출물 | 총점 밴드 ±5점 + 레벨 4단계 + 축 플래그 3단 |
| 조직 산출물 | n≥10에서 축별 평균·신뢰구간·오답 집중 문항·레벨 분포 |

주관식은 **4차원 × 5점 루브릭**(위임 경계 / 규격 구체성 / 검증 설계 / 전환 효과)에 리스크 감점을 더해 채점한다. LLM 채점은 차원별 독립 4패스 + 감점 1패스로 돌린다 — [rubrics/llm-scorer-prompt.md](rubrics/llm-scorer-prompt.md).

## 빠른 시작

### 온라인 응시본 생성

```bash
python3 scripts/build_web_form.py   # items/ -> forms/form-A.web.html
```

35분 타임박스, 구간별 잔여 시간, 공통 지문 고정 표시, 구간·문항별 소요 시간 자동 기록. **정답을 포함하지 않으므로 자가 채점 기능이 없다** — 넣으면 개발자 도구로 정답이 읽힌다. 응답은 서버에 저장되지 않고 응시자가 직접 내보낸다.

### 문항 뱅크 정합성 검사

```bash
python3 scripts/lint_items.py
```

축 배분 · 난이도 · 정답 위치 · stance 균형 · 시간 예산 · 선택지 길이 비율 · 오답 진단 완전성 · 금지 패턴 · 응시본 정답 누출 · 응시본↔문항 동기화 · 상대 링크를 한 번에 검사한다. **의존성 없음(표준 라이브러리만).** 문항을 고친 뒤 커밋 전에 반드시 실행한다.

### 시행 전 필수 조건

> **[스폰서 합의문](docs/09-sponsor-agreement.md)에 서명이 없으면 진단을 시행하지 않는다.**

진단 결과를 쓸 계획이 없는 조직에서 진단은 리포트 한 장으로 끝나고, 이 프로젝트가 고치려던 그 실패(진단 반영 3.6%)를 재생산한다. 교육 실패 원인의 68%는 문항 품질이 아니라 ① 경영진 리스크 ② 출구 전략 부재이고, 둘 다 문항으로는 해결되지 않는다.

## 불가침 규칙

어기면 진단이 무효가 된다. 전문은 [AGENTS.md](AGENTS.md)와 [docs/00-charter.md](docs/00-charter.md).

| # | 규칙 | 왜 |
|---|---|---|
| 1 | **축별 점수를 숫자로 내보내지 않는다** | 축당 4문항에서 2/4와 3/4는 통계적으로 구별되지 않는다. 3단 플래그만 쓴다 |
| 2 | **개인 리포트에 축별 레이더 차트를 그리지 않는다** | 4문항으로 5각 레이더를 그리는 것은 과잉 주장이다 |
| 3 | **툴 상식 문항을 추가하지 않는다** | 모델명·용어 정의는 6개월이면 바뀌고 업무 수행과 상관이 거의 없다 |
| 4 | **교육 설계용과 인사 평가용을 한 폼으로 겸하지 않는다** | 겸용하면 응시자가 점수를 방어하기 시작해 진단 데이터가 오염된다 |
| 5 | **`forms/`를 손으로 고치지 않는다** | 지필·온라인 응시본 모두 생성물이다. 드리프트는 린트가 잡는다 |
| 6 | **`pilot/responses/`를 커밋하지 않는다** | 무기명 시행을 약속했다면 레포에 응답이 들어가는 순간 그 약속이 거짓이 된다 |

## 검증 현황

문항 뱅크는 실행 가능한 코드가 아니므로 **린트 → 자가 응시 → 파일럿** 3단으로 검증한다.

| 단계 | 상태 | 내용 |
|---|:---:|---|
| **1단** 뱅크 정합성 린트 | ✅ 완료 | 16개 검사 전항목 PASS. `scripts/lint_items.py`로 자동화 |
| **2단** 채점 리허설 (C0) | ✅ 완료 | 앵커 12개 + 페이킹 답안 2개. 결함 11건 발견 → 전부 반영 |
| **2단** 재검증 (C1) | ✅ 완료 | **채점 모델을 바꿔**(Opus 작성 → Sonnet 채점) 재실행. 네 차원 전부 ±1, **±2 이상 0건** |
| **2단** 소요 시간 | ◐ 추정만 | 예산 정합성 검사 결과 **32~35분** — 목표(35분 ±3분) 안이다. 실측은 사람이 타이머를 켜고 응시해야 한다 |
| **3단** 파일럿 | ⬜ 대기 | 10~15명, 레벨 혼합 선정. 스폰서 서명이 선행 조건 |

### 2단에서 나온 것

| 통과 조건 | 판정 |
|---|:---:|
| 앵커 12개 D1 차이 ±1 이내 | ✅ |
| FR-02 L1-b 감점 −5 탐지 | ✅ |
| 감점의 이중 처벌 없음 | ✅ |
| FR-01 페이킹 답안 D2·D4 상한 2점 | ✅ |
| FR-02 페이킹 답안 D2·D3 상한 3점 | ◐ 부분 |

C0에서 결함 11건이 나왔고 전부 반영했다. 통과 조건이 D1만 검사하도록 설계되어 있어서 D2·D3의 앵커 오류 5건이 통과 판정에 가려졌던 것이 가장 컸다 — 통과 조건을 **네 차원 전부 ±1**로 강화했다.

C1에서 **채점 모델을 바꿔** 재검증한 결과, 정정값이 전부 독립 재현됐다. 페이킹 방어의 대조쌍이 특히 깨끗하다 — 실제 만점 앵커와 페이킹 답안은 **골격이 거의 같고 고유명사 유무만 다른데 20/20 대 8/20**으로 갈린다.

**남은 큰 문제 둘**

- FIN 페르소나를 고른 답안은 두 회차·두 모델에서 **예외 없이 감점**을 받았다. 페르소나 조건을 하나도 쓰지 않은 범용 답안까지 −5가 나왔다. 지금 상태로는 감점 발생률이 역량이 아니라 **페르소나 선택 분포**를 측정한다
- 페이킹 방어 상한이 *언제 켜지는지*가 불안정하다. 같은 답안에 대해 채점 패스마다 적용 판정이 갈렸고, 페르소나만 바꿔도 뒤집혔다. **범용 답안이 "자료에 없는 내용은 쓰지 마라" 한 줄로 우회할 수 있다**

앵커 세트도 보강했다. 신규 앵커는 **점수를 비운 채 다른 모델로 먼저 채점해 의도와 수렴하는 것을 확인한 뒤** 확정한다 — 답안을 쓴 쪽이 점수까지 매기면 검증이 아니다. 후보 3종 중 2종을 채택하고 1종은 폐기했다.

시간 예산 정합성 검사에서는 **린트가 공통 지문 길이·`stem_ref` 참조를 검사하지 않던 것**을 찾아 검사를 추가했다. (같은 검사의 1차 결과에서 지문이 상한을 초과한다고 보고했으나, 측정 스크립트의 섹션 추출 버그였고 철회했다 — 경위를 결함 기록 부록에 남겼다.)

> ⚠️ **2단 결과는 독립 검증이 아니다.** 앵커와 부여 점수를 쓴 것과 같은 모델 계열이 채점했다. 일치 항목은 타당도의 증거가 아니고, **불일치 항목만 신호**로 취급한다. 수렴 타당도는 인간 채점자 또는 다른 계열 모델이 붙어야 나온다.

### 알려진 한계 (리포트에 숨기지 않는다)

| 한계 | 완화 |
|---|---|
| 축당 4문항 → 개인 축별 점수 산출 불가 | 3단 플래그 + 자기보고 삼각검증. n≥30 코호트 단위 해석 |
| 공통 지문 국소 종속성 → 내적 일관성 과대추정 | 블록 3문항, 블록 내 축 전부 다르게. alpha를 리포트에 쓰지 않는다 |
| DEL–FLW 상관 예상 0.5+ | 두 축을 레이더로 나란히 제시하지 않는다 |
| 지필 시험 → 실제 도구 사용을 직접 관측 못함 | 주관식 프롬프트 첨부 요구가 부분 대용. v2에서 실제 수행 과제 |
| 자기보고 조작 가능 | 점수에 절대 반영하지 않고 플래그 하향에만 사용 |

## FAQ

<details>
<summary><b>왜 축별 점수를 안 주나요?</b></summary>

축당 4문항, 문항 정답률 0.6을 가정하면 축 소점수의 95% 신뢰구간이 ±2문항 수준이다. **2/4와 3/4가 구별되지 않는다.** 숫자로 보고하는 순간 그것은 거짓말이 된다. 대신 강점 신호 / 판정 보류 / 보완 필요 3단 플래그를 쓰고, 자기보고와 불일치하면 판정 보류로 내린다. → [docs/04-scoring.md](docs/04-scoring.md)
</details>

<details>
<summary><b>왜 모델명이나 프롬프트 기법을 안 묻나요?</b></summary>

B2B에서 알아야 할 것은 툴 지식이 아니라 **이 사람과 이 조직이 AI를 잘 쓸 역량을 갖췄는가**다. 모델명·기능명은 6개월이면 바뀌고, 그걸 아는 것과 업무에 쓰는 것 사이에 상관이 거의 없다. 툴 상식 문항은 출제 규칙에서 **금지**되어 있고 린트가 일부를 기계적으로 잡는다.
</details>

<details>
<summary><b>응시자가 AI로 주관식을 대신 쓰면요?</b></summary>

**막지 않는다. 쓸모없게 만든다.** AI 사용을 허용하되 사용한 프롬프트를 첨부하게 하고, 그 프롬프트를 채점 자료로 함께 쓴다. FR-01은 실제 업무명·시스템명·데이터 항목명이 없으면 D2·D4가 상한 2점에 갇히고, FR-02는 페르소나 지문 조건을 쓰지 않으면 D2·D3이 상한 3점에 갇힌다.

다만 **2단 리허설에서 이 방어가 절반만 작동하는 것을 확인했다** — 상한이 D1·D3에는 없어서 내용이 없는 답안도 FR-01에서 14/20을 받는다. 미해결 과제다. → [docs/10-calibration-findings.md](docs/10-calibration-findings.md)
</details>

<details>
<summary><b>인사 평가에 쓰면 안 되나요?</b></summary>

같은 시험을 교육 설계용과 인사 평가용으로 겸용하면 응시자가 점수를 방어하기 시작하면서 **진단 데이터가 오염되고 교육 설계 근거가 사라진다.** 인증 회차를 운영하려면 별도 문항풀을 새로 만들어야 하고, 본 뱅크 문항을 인증에 쓰면 그 문항은 진단용으로 폐기된다. → [docs/00-charter.md](docs/00-charter.md) 2트랙 정책
</details>

<details>
<summary><b>주관식 LLM 채점은 믿을 만한가요?</b></summary>

아직 검증 중이다. 프로토콜은 차원별 독립 4패스 + 감점 1패스를 요구하고(한 번에 4차원을 채점하면 총점 선입견이 차원 간 점수를 서로 끌어당긴다), 회차 시작 전 앵커 캘리브레이션을 통과해야 실제 응답을 채점할 수 있다. 실제 시행에서는 **LLM 전수 + 인간 20% 표본** 이중 채점을 하고, 어느 차원에서든 2점 이상 불일치하면 인간 판정을 채택한다.
</details>
