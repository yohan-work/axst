# training/ — 진단 결과에 맞춘 실습 키트

진단은 **어디가 약한지**를 알려주고, 이 폴더의 키트는 **그 약한 곳을 연습하게** 한다. 개인 리포트의 "다음 행동" 칸이 가리키는 곳이 여기다.

처방 원칙(레벨별 트랙, 코호트 편성, 교육으로 안 풀리는 것)은 [docs/06-prescription.md](../docs/06-prescription.md)가 정본이다. 이 폴더는 그중 **"약점 축 → 교육 내용"을 실제로 해볼 수 있는 자료**로 만든 것이다.

## 키트를 만드는 원칙

새 키트를 쓸 때 지킨다. 검증 키트가 이 원칙의 첫 사례다.

1. **시험 문항을 재사용하지 않는다.** 원리는 같게, 장면은 새로 만든다. **선택지 구성도 복제하지 않는다** — 장면만 바꾸고 같은 네 가지 반응을 늘어놓으면 재진단에서 알아보기만으로 맞힌다.
2. **정답이 키트 안의 자료만으로 확정되게 만든다.** diff, 로그, 사내 문서 발췌를 자료로 주고 그 안에서 판정한다. 외부 사실이나 작성자의 상식("AI는 ○○를 못 한다")에 기대면 작성자가 틀릴 수 있고 학습자도 확인하기 어렵다. 판정에 필요한 전제는 **상황 설명에 적는다.**
3. **진단 리포트의 "생각의 습관" 문구를 해설에서 글자 그대로 부른다.** 학습자가 "리포트가 말한 게 이거구나"를 알아보게 한다. 문구의 정본은 각 문항 파일의 `distractor_dx`이고, 리포트는 이 문구를 그대로 출력한다.
4. **마지막 실습은 본인 업무로 한다.** 점검표는 좋은 산출물의 요소로 쓴다.
5. **교육으로 안 풀리는 것은 팀 장치로 넘긴다.** 키트 끝에 팀에 둘 장치(템플릿·체크리스트)를 하나씩 붙인다.
6. **직무별로 만든다.** 장면이 내 일이 아니면 학습자가 옮겨 쓰지 못한다. 검증 키트는 프론트엔드·웹퍼블리싱판이고, 다른 직무판은 같은 뼈대에 장면만 바꾼다.
7. **해설은 블라인드로 검증한다.** 해설을 주지 않은 채 다른 모델이나 사람에게 풀게 해서, 정답이 자료만으로 하나로 정해지는지 확인한 뒤 확정한다. 답을 쓴 쪽이 스스로 검토하는 것은 검증이 아니다.

## 팀 세션 진행안 (60분)

혼자 50분짜리를 팀 세션으로 돌릴 때.

| 시간 | 할 일 |
|---|---|
| 0–3분 | 각자 키트 0번(지금의 나)을 적는다. 공유하지 않는다 |
| 3–10분 | 진행자가 규칙 한 장(1절)을 읽는다 |
| 10–25분 | 실습 1을 **혼자** 푼다. 순서표만 채운다 |
| 25–35분 | 둘씩 짝지어 순서를 비교하고, **1번이 다른 짝**이 전체에 이유를 말한다 |
| 35–40분 | 진행자가 해설의 모범 순서와 "습관이 드러나는 자리" 표를 보여준다 |
| 40–45분 | 실습 2를 함께 푼다 |
| 45–58분 | 실습 3을 각자 시작한다. 끝내지 못하면 과제로 |
| 58–60분 | 0번 답을 다시 보고, 무엇이 바뀌었는지 한 줄 |

**진행자 주의**
- 실습 1에서 누가 틀렸는지 지목하지 않는다. 이 진단의 결과는 교육 설계에만 쓰고 평가에 쓰지 않는다는 원칙([docs/00-charter.md](../docs/00-charter.md))이 세션에도 적용된다.
- 실습 3의 "다섯 요소"는 진단 주관식의 검증 설계 채점 기준과 같은 틀이다. 학습자에게 **점수 이야기로 설명하지 않는다** — 채점표를 익히는 교육이 되면 재진단 점수가 역량을 말해 주지 못한다.

## 팀에 두는 장치: PR 템플릿 세 줄

실습 1이 보여준 세 가지 함정을 PR 템플릿에 넣는다. 교육은 잊히지만 템플릿은 매번 보인다.

```markdown
### AI가 쓴 요약을 그대로 올렸다면 확인
- [ ] "없음 · 전체 · 문제없음" 주장을 실제로 찾아봤다 (다른 사용처, 돌지 않은 테스트)
- [ ] 통과했다는 검사의 **범위**를 확인했다 (어느 폴더, 몇 개 스위트)
- [ ] 수행 기록 없이 "확인했다"는 문장("브라우저에서 확인", "모니터링 결과")을 지우거나 사람이 확인했다
```

## 효과를 확인하는 법

| 언제 | 무엇을 | 무엇이 변하면 효과인가 |
|---|---|---|
| 키트 직후 | 0번과 5번의 답 비교 | 첫 확인 대상이 "없다·전체" 주장으로 옮겨갔다 |
| 2~4주 뒤 | 팀 PR에서 세 줄 점검 사용 여부 | 체크된 PR에서 범위 오류·근거 없는 문장이 걸러졌다 |
| 8~12주 뒤 | 재진단 ([docs/06 §6](../docs/06-prescription.md#6-재진단)) | 검증 축 신호가 🟠 → ⚪/🟢 |

**재진단 해석의 제한** — 키트가 가르친 것과 겹치는 지표는 효과의 증거로 약하다.

- **주관식 검증 설계 점수**: 실습 3이 좋은 검증 계획의 요소를 연습시키므로, 점수가 올라도 역량이 는 것인지 요소를 익힌 것인지 구별되지 않는다. 참고 지표로만 쓴다.
- **`MC-VER-004`(인용을 무엇으로 믿는가)**: 실습 2와 원리가 겹친다. 이 문항의 상승은 키트 효과의 증거로 쓰지 않는다.
- 강한 증거는 **키트가 직접 다루지 않은 장면**의 검증 문항과, 2~4주 뒤 실제 PR에서의 변화다.

재진단은 공개된 폼 A가 아니라 **비공개 시행 폼**으로 한다([docs/08](../docs/08-administration.md#폼-분리-공개-참조-폼과-시행-폼)).
