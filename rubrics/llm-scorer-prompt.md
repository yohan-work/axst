# LLM 채점 프로토콜

주관식 FR-01 / FR-02를 LLM으로 채점할 때의 절차와 프롬프트. 목적은 **인간 채점자와 ±1점 내로 수렴시키는 것**이다.

## 프로토콜 (순서를 바꾸지 않는다)

| # | 단계 | 규칙 |
|---|---|---|
| 1 | **앵커 캘리브레이션** | 회차 시작 시 [fr-01-anchors.md](fr-01-anchors.md) / [fr-02-anchors.md](fr-02-anchors.md)의 앵커 답안을 먼저 채점한다. 부여된 레벨과 **±1점 내에 들지 않으면** 프롬프트를 수정하고 재실행한다. 통과 전에는 실제 응답을 채점하지 않는다 |
| 2 | **차원별 독립 패스 4회** | D1, D2, D3, D4를 **각각 별도 호출**로 채점한다. 한 번에 4차원을 채점하면 총점에 대한 선입견이 생겨 차원 간 점수가 서로를 끌어당긴다 |
| 3 | **감점 판정 1회** | [penalty-risk.md](penalty-risk.md)를 5번째 독립 패스로 적용한다. 차원 채점과 섞으면 감점 사유가 D1을 오염시킨다 |
| 4 | **이중 채점** | LLM 전수 + 인간 **20% 표본**. 어느 차원에서든 **2점 이상 불일치**하면 인간 판정을 채택하고, 그 사례를 앵커 파일에 추가한다 |

**모델 설정**: temperature 0. 각 패스는 독립 컨텍스트(이전 패스의 점수를 보여주지 않는다).

## 각 패스가 강제하는 출력 순서

> **근거 인용 → 카운트 → 점수**

순서를 강제하는 이유: 점수를 먼저 내면 근거를 사후에 맞춘다. 응답자의 원문을 그대로 인용하게 하면 근거 없는 점수가 구조적으로 불가능해진다.

## 프롬프트 템플릿 — 카운트형 차원 (D2, D3)

```
당신은 기업 AI 역량 진단의 주관식 채점자다. 아래 루브릭 한 차원만 채점한다.
다른 차원은 채점하지 않고, 총점을 추정하지 않는다.

[루브릭]
{rubrics/fr-0N.md 에서 해당 차원 절만 붙여넣기}

[응시자 답안]
{답안 전문}

[첨부 프롬프트]  ← ai_use_disclosure로 제출된 경우에만
{첨부 프롬프트 전문}

다음 순서로만 출력한다. 순서를 바꾸지 않는다.

1. 요소별 근거 인용
   각 요소(①~⑤ 또는 ①~④)에 대해, 답안에서 그 요소를 충족한다고
   판단한 문장을 원문 그대로 인용한다. 충족하지 않으면 "없음"이라고만 쓴다.
   원문에 없는 내용을 요약하거나 보충하지 않는다.
   형용사만 있으면 "없음"으로 처리한다(루브릭의 인정 기준 참조).

2. 카운트
   충족한 요소 번호를 나열하고 개수를 쓴다. 예: ①②④ = 3개

3. 점수
   루브릭 표의 개수-점수 대응을 그대로 적용한 점수 1개.
   상한 제한 조건(required_anchors 미충족 / 페르소나 조건 미사용 /
   지시문 미작성)에 해당하면 적용하고 그 사실을 명시한다.

출력 형식:
근거 인용:
  ①: "..." 또는 없음
  ②: ...
카운트: ①② = 2개
상한 제한: 없음 / 적용(사유)
점수: 3
```

## 프롬프트 템플릿 — 판단형 차원 (D1, D4)

```
당신은 기업 AI 역량 진단의 주관식 채점자다. 아래 루브릭 한 차원만 채점한다.
다른 차원은 채점하지 않고, 총점을 추정하지 않는다.

[루브릭]
{해당 차원 절 + 채점 시 주의 전부}

[앵커 답안]
{fr-0N-anchors.md 의 해당 차원 레벨 1/3/5 앵커 6개 전부}

[응시자 답안]
{답안 전문}

다음 순서로만 출력한다.

1. 근거 인용
   이 차원에 해당하는 서술을 답안에서 원문 그대로 인용한다.
   해당 서술이 없으면 "없음"이라고 쓴다.

2. 앵커 대조
   위 앵커 6개 중 이 답안과 가장 가까운 것을 지목하고,
   어느 점에서 같고 어느 점에서 다른지 한 문장으로 쓴다.

3. 레벨 요건 점검
   루브릭의 각 레벨 요건을 아래에서 위로 점검한다.
   - 3점 요건(기준이 판단의 성격에 근거)을 충족하는가? 예/아니오 + 근거
   - 4점 요건(최종 판단 주체 명시)을 충족하는가? 예/아니오 + 근거
   - 5점 요건(예외 상황 + 처리)을 충족하는가? 예/아니오 + 근거
   D1의 경우 겉보기 human-in-the-loop 감별을 반드시 수행한다:
   AI가 선택지 집합을 만들고 사람이 그중 고르는 구조만 있으면 최대 3점.

4. 점수
   점수 1개와 한 문장 사유.

출력 형식:
근거 인용: "..."
가장 가까운 앵커: L3-a (같은 점: ... / 다른 점: ...)
요건 점검: 3점 ✅ / 4점 ❌ / 5점 ❌
점수: 3
사유: ...
```

## 프롬프트 템플릿 — 감점 패스

```
당신은 기업 AI 역량 진단의 리스크 감점 판정자다.
점수를 매기지 않고, 감점 해당 여부만 판정한다.

[감점 규칙]
{rubrics/penalty-risk.md 전문}

[응시자 답안]
{답안 전문}

다음 순서로만 출력한다.

1. 민감 데이터·외부 공개 관련 서술을 답안에서 원문 그대로 인용한다.
   없으면 "없음".
2. 감점 규칙의 "감점하지 않는 것" 목록과 대조해, 해당하는 항목이 있으면 지목한다.
3. 판정: -5 / -2 / 0 중 하나와 적용한 규칙 문장.

중요:
- 리스크를 언급하지 않았다는 사실만으로는 감점하지 않는다.
- 사내 전용 도구에 사내 데이터를 넣는 것은 감점하지 않는다.
- 판정이 애매하면 감점하지 않는다(0으로 판정한다).
- AI를 쓰지 않겠다는 답안에 가점하지 않는다.

출력 형식:
인용: "..." 또는 없음
감점 예외 해당: 있음(항목) / 없음
판정: 0
적용 규칙: 해당 없음
```

## 집계

5개 패스의 출력을 모아 계산한다.

```
합계 = max(0, D1 + D2 + D3 + D4 + 감점)
```

응답별로 [fr-01.md](fr-01.md)의 채점 기록 양식에 맞춰 저장한다. 근거 인용을 반드시 함께 보관한다 — 인간 표본 재채점 시 불일치 원인을 찾는 데 이것만 쓰인다.

## 캘리브레이션 실패 시

앵커를 ±1점 내로 못 맞히는 경우의 처리 순서.

1. **어느 방향으로 틀리는지 본다.** 전반적으로 관대하면 "형용사만 있으면 없음으로 처리한다"를 강조하고, 전반적으로 엄격하면 인정 기준 예시를 프롬프트에 추가한다.
2. **특정 앵커 하나만 못 맞히면 그 앵커가 모호한 것이다.** 앵커를 교체하거나 그 레벨의 요건 문장을 다듬는다.
3. **D1에서 반복 실패하면 앵커를 늘린다.** D1은 유일한 저신뢰 차원이므로 레벨당 앵커를 2개에서 3개로 늘린다.
4. 세 번 수정해도 통과하지 않으면 **해당 회차는 인간 전수 채점으로 전환**하고, 그 회차 응답에서 새 앵커를 뽑는다.
