# FR-01 채점 루브릭 — 본인 업무의 위임·재설계

**대상 문항**: [items/fr/FR-01.md](../items/fr/FR-01.md)
**축**: 위임 판단력(DEL) + 워크플로우 재설계(FLW)
**배점**: 4차원 × 5점 = **20점** (감점 규칙 적용 후 하한 0)

## 공통 채점 원칙

> **존재하면 2점, 구체적이면 4점, 반례·예외까지 다루면 5점.**

- **구체적**의 정의: 형용사가 아니라 **수치·고유명사·예시**가 있다. "빠르게"는 구체적이지 않고 "주 2회, 화·목 오전"은 구체적이다.
- `required_anchors`(담당 업무명 / 사내 시스템명 / 데이터 항목명) 중 **하나도 등장하지 않으면 D1·D2·D3·D4 네 차원 전부의 상한을 2점으로 제한한다.** 본인 업무에 대한 답이 아니라는 뜻이므로.
- **왜 네 차원 전부인가**: 회차 C0에서 상한을 D2·D4에만 걸었더니, 업무 내용이 한 글자도 없는 범용 답안이 D1 5점·D3 5점을 그대로 받아 **14/20**을 획득했다. 위임 경계와 검증 설계는 고유명사 없이도 형식만으로 쓸 수 있다. 상한을 네 차원에 걸면 같은 답안이 8/20에 갇힌다. 근거는 [docs/10-calibration-findings.md](../docs/10-calibration-findings.md) 결함 6.
- 분량이 `answer_min_chars`(400자) 미만이면 각 차원을 **있는 그대로** 채점한다. 분량 자체로 감점하지 않는다.

---

## D1. 위임 경계와 책임 귀속 (5점)

무엇을 AI에 맡기고 무엇을 사람이 쥐는지, **그 기준이 무엇인지**를 본다.

| 점 | 답안의 모습 |
|---|---|
| **1** | AI에 맡길 것과 사람이 할 것의 구분이 없다. "AI로 처리하겠다" 수준 |
| **2** | 구분은 있으나 **기준이 작업량이거나**("쉬운 일/어려운 일", "많은 일/적은 일") **기준을 아예 밝히지 않았다** |
| **3** | 구분이 있고 기준이 **판단의 성격**(책임 귀속·되돌릴 수 없음·해석의 여지)에 근거한다 |
| **4** | 3 + **최종 판단 주체를 사람 이름 또는 역할로 명시**하고, AI 산출물이 그 판단에 어떻게 투입되는지 적었다 |
| **5** | 4 + **경계가 흔들리는 예외 상황 1개**와 그때의 처리(에스컬레이션·보류·재검토)를 적었다 |

**채점 시 주의**
- "검토는 제가 합니다"만 있으면 3점이 아니다. 무엇을 기준으로 무엇을 검토하는지가 없으면 2점.
- **겉보기 human-in-the-loop 감별**: AI가 3개 안을 만들고 사람이 그중에서 고른다는 서술은 사람이 판단한 것이 아니라 선택지 집합을 AI가 정한 것이다. 이 구조만 있으면 **최대 3점**. **상한이지 하한이 아니다** — 위임 기준 서술이 없으면 2점이다.
- 반대로 "AI에게 내 판단의 반론을 요청한다" 같은 서술은 판단을 사람이 보유한 것이므로 4점 요건에 부합한다.

**상한**: `required_anchors`가 전혀 없으면 상한 2점.

**IRR 경고**: [fr-01-anchors.md](fr-01-anchors.md)의 앵커 답안 6개를 반드시 먼저 읽고 채점한다. 앵커 없이는 인간–LLM 일치가 나지 않는다. 단 **캘리브레이션 회차에서는 앵커를 주지 않는다**([llm-scorer-prompt.md](llm-scorer-prompt.md)).

## D2. 맥락·제약·산출물 규격의 구체성 (5점) — 카운트형

아래 5요소 중 **명시적이고 구체적인 것의 개수**를 센다.

| | 요소 | 인정 기준 |
|---|---|---|
| ① | 수신자·용도 | 누가 읽고 무엇에 쓰는지 |
| ② | 투입 데이터의 범위와 출처 | 어느 시스템의 어느 항목, 어느 기간 |
| ③ | 금지·제약 조건 | 하지 말아야 할 것, 넣지 말아야 할 것 |
| ④ | 산출물 구조·분량·형식 | 항목 구성, 장수/자수, 표/문장 |
| ⑤ | 톤/품질 기준 또는 예시 | 기준 문장, few-shot 예시 |

| 점 | 기준 |
|---|---|
| **1** | 0–1개 |
| **2** | 2개 |
| **3** | 3개 |
| **4** | 4개 |
| **5** | 5개 전부 + 그중 **3개 이상이 수치·고유명사·예시로 구체화**됨 |

**채점 시 주의**
- 형용사만 있으면 세지 않는다. "간결하게"는 ⑤가 아니고 "3문장 이내, 결론 먼저"는 ⑤다.
- `ai_use_disclosure`로 첨부된 프롬프트가 있으면 **그 프롬프트를 이 차원의 근거로 그대로 쓴다.** 본문에 없고 첨부 프롬프트에만 있는 요소도 인정한다.
- `required_anchors`가 전혀 없으면 상한 2점.

## D3. 검증 설계 (5점) — 카운트형

| | 요소 | 인정 기준 |
|---|---|---|
| ① | 검증 대상 지정 | 어느 수치·어느 주장을 볼 것인지 특정 |
| ② | 검증 방법 | 원자료 대조 / 재계산 / 독립 재생성 후 비교 / 타인 리뷰 중 무엇인지 |
| ③ | 실패 시 행동 | 틀렸을 때 무엇을 하는지 |
| ④ | 검증 주체·시점 | 누가, 언제(발송 전/보고 전 등) |

| 점 | 기준 |
|---|---|
| **1** | "확인하겠다" 등 방법 없는 언급, 또는 없음 |
| **2** | 1개 요소 |
| **3** | 2개 요소 |
| **4** | 3개 요소, 방법이 **실행 가능한 수준**으로 기술됨 |
| **5** | 4개 전부 + **검증 비용을 의식한 우선순위**(무엇을 먼저 볼지 / 무엇은 안 볼지)를 밝혔다 |

**채점 시 주의**
- "꼼꼼히 검토한다", "여러 번 확인한다"는 ②가 아니다. 무엇과 무엇을 대조하는지가 있어야 한다.
- `required_anchors`가 전혀 없으면 상한 2점.
- "전부 확인한다"는 5점 요건이 아니다. 5점은 **안 볼 것을 정하는 판단**을 요구한다.

---

## D4. 업무 전환 효과 (5점)

| 점 | 답안의 모습 |
|---|---|
| **1** | 효과 언급 없음, 또는 "효율화된다" |
| **2** | **시간 절감만** 말한다 ("주 3시간 단축") |
| **3** | 사라지거나 줄어드는 **구체적 작업 단계를 이름으로** 지목했다 |
| **4** | 3 + 절감된 시간이 **무엇으로 전환되는지** 적었다 |
| **5** | 4 + 이 방식을 **타인·팀에 전파하는 경로**(문서화/템플릿/담당자 지정)와 **성과 보고 지표**를 적었다 |

**채점 시 주의**
- 2점과 3점의 경계가 핵심이다. "보고서 작성이 빨라진다"는 2점, **"5개 부서 양식을 손으로 맞추는 단계가 없어진다"**는 3점.
- 이 차원의 2점 상한은 원문의 측정 트랩을 그대로 반영한다 — 시간 절감만 보고하면 "남는 시간에 뭘 했는지"를 되묻게 되고 거기서 보고가 멈춘다.
- `required_anchors`가 전혀 없으면 상한 2점.

---

## 감점 적용

D1–D4 합계에 [penalty-risk.md](penalty-risk.md)의 감점을 적용한다. 하한 0점.

## 채점 기록 양식

각 응답에 대해 아래를 남긴다. LLM 채점도 같은 형식으로 출력한다.

```
응답 id:
D1 위임경계: _점 | 근거 인용: "..."
D2 구체성:   _점 | 카운트: ①②④ = 3개 | 근거 인용: "..."
D3 검증설계: _점 | 카운트: ①② = 2개 | 근거 인용: "..."
D4 전환효과: _점 | 근거 인용: "..."
감점: _점 | 해당 규칙:
합계: _/20
required_anchors 충족: 담당업무명 ✅ / 사내시스템명 ❌ / 데이터항목명 ✅
```
