# FR-02 채점 루브릭 — 페르소나 상황의 지시 설계와 검증

**대상 문항**: [items/fr/FR-02.md](../items/fr/FR-02.md)
**축**: 작업 설계(DSN) + 검증·신뢰 조정(VER)
**배점**: 4차원 × 5점 = **20점** (감점 규칙 적용 후 하한 0)

FR-01과 **같은 4차원**을 쓴다. 다만 FR-02는 응시자가 선택한 직무 페르소나 상황이 주어지고 **실제 지시문을 작성**하게 하므로, D2와 D3이 주 변별 차원이다. 채점 원칙과 기록 양식은 [fr-01.md](fr-01.md)와 동일하다.

## 공통 채점 원칙

> **존재하면 2점, 구체적이면 4점, 반례·예외까지 다루면 5점.**

- **구체적**의 정의: 형용사가 아니라 **수치·고유명사·예시**가 있다.
- FR-02는 `required_anchors`가 없다(본인 업무가 아니라 부여된 페르소나 상황이므로). 대신 **페르소나 항목명 지목**을 본다. 답안 어디에도 선택한 페르소나의 **고유 데이터 항목명**(`personas/*.md`의 `anchor_items` — 예: `계정 과목`, `불량 유형 코드`)이 **하나도 없으면** **D1·D2·D3·D4 네 차원 전부의 상한을 3점**으로 제한한다 — 범용 템플릿 답안이라는 뜻이다. FR-01과 같은 이유다([fr-01.md](fr-01.md) 공통 원칙).
  - 근거: [docs/10-calibration-findings.md](../docs/10-calibration-findings.md) 결함 6·17. *(이 줄은 채점 패킷에서 제거된다. 규칙 문장과 같은 줄에 회차·결함 번호를 쓰지 않는다.)*
  - **판정은 기계적으로 한다.** 항목명이 **한 낱말로** 등장하는지만 본다. 항목명 글자 사이의 띄어쓰기는 무시하고(`반려사유코드`는 `반려 사유 코드`로 인정) 뒤에 붙는 조사는 허용하지만(`작업조별`), 다른 낱말의 일부는 인정하지 않는다(`작업 조건`은 `작업조`가 아니다). 페르소나를 선택하지 않은 답안은 판정 보류다. `scripts/score.py --prompts`가 답안마다 판정을 미리 적어 준다. 채점자는 이 판정을 바꾸지 않는다.
  - `anchor_items`에는 지문의 데이터 항목 중 **그 페르소나에만 있는 것**만 넣는다. `부서`·`담당자`·`서비스`·`거래처`처럼 어느 보고서에나 나올 일반어는 범용 답안도 우연히 쓰므로 뺐다.
  - **어느 페르소나에도 붙일 수 있는 일반 서술은 지목이 아니다.** "자료에 없는 내용은 쓰지 마라", "수신자는 임원", "1장 분량"은 페르소나를 몰라도 쓸 수 있다. 이런 문구로 상한을 피할 수 있으면 페이킹 방어가 한 줄로 무력화된다.
- 지시문을 **실제 문장으로 작성하지 않고** "이렇게 지시할 것이다"라고 설명만 한 답안은 D2 상한 **3점**.

---

## D1. 위임 경계와 책임 귀속 (5점)

FR-02의 페르소나 상황에서 **무엇을 AI에 맡기고 무엇을 사람이 쥐는지**.

| 점 | 답안의 모습 |
|---|---|
| **1** | 구분이 없다. 전부 AI에 맡기는 지시문만 있다 |
| **2** | 구분은 있으나 **기준이 작업량이거나**("반복 작업은 AI") **기준을 아예 밝히지 않았다** |
| **3** | 기준이 **판단의 성격**(책임 귀속·되돌릴 수 없음·해석의 여지)에 근거한다 |
| **4** | 3 + 페르소나 상황에서 **최종 판단 주체를 역할로 명시**하고 AI 산출물이 그 판단에 어떻게 투입되는지 적었다 |
| **5** | 4 + **경계가 흔들리는 예외 1개**와 처리 방법 |

**겉보기 human-in-the-loop 감별**: AI가 안을 만들고 사람이 고른다는 구조만 있으면 최대 3점. **상한이지 하한이 아니다** — 위임 기준 서술이 없으면 2점이다. [fr-02-anchors.md](fr-02-anchors.md)를 먼저 읽는다.

**상한**: 페르소나 항목명을 하나도 지목하지 않았으면 상한 3점.

---

## D2. 지시문의 규격 구체성 (5점) — 카운트형 ★주 변별 차원

응시자가 작성한 **실제 지시문**에서 아래 5요소를 센다.

**어디서 세는가**: **② 지시 설계 항목**과 **첨부 프롬프트** 안에서만 센다. ①·③·④ 항목에만 있는 내용은 세지 않는다. 지시문 대신 설명을 쓴 답안도 ② 항목 안에서 세되 아래 상한(3점)을 적용한다.

| | 요소 | 인정 기준 |
|---|---|---|
| ① | 수신자·용도 | 페르소나 상황의 실제 수신자가 ② 항목에 들어 있다. **승인자·검토자만 있으면 인정하지 않는다** |
| ② | 투입 데이터의 범위와 출처 | 페르소나 지문에 주어진 데이터 항목·기간을 특정 |
| ③ | 금지·제약 조건 | 넣지 말 것, 추측하지 말 것, 없는 수치를 만들지 말 것 등 |
| ④ | 산출물 구조·분량·형식 | **산출물의 모양과 분량** — 항목 구성, 장수/자수(항목별 분량 포함), 표/문장 |
| ⑤ | 톤/품질 기준 또는 예시 | **문장이 무엇을 어떤 순서로 담아야 하는지**의 기준이나 예시 — 문장 틀("요약은 '서비스 – 변화 – 확인 필요' 순서로 써라"), 좋은 예·나쁜 예, 따라 할 기존 문서 지정 |

**④와 ⑤의 경계**는 [fr-01.md](fr-01.md) D2와 같다 — ④는 모양과 분량(**항목별 분량도 ④**: "3줄 요약", "각 2줄"), ⑤는 문장에 무엇을 어떤 순서로 담는지의 틀이나 예시. 한 문장은 한 요소로만 센다. 형용사("깔끔하게", "친근하고 트렌디하게")는 ⑤가 아니다.

**상한**: 페르소나 항목명을 하나도 지목하지 않았으면 상한 3점. 지시문을 실제 문장으로 쓰지 않고 설명만 했으면 상한 3점.

| 점 | 기준 |
|---|---|
| **1** | 0–1개 |
| **2** | 2개 |
| **3** | 3개 |
| **4** | 4개 |
| **5** | 5개 전부 + 그중 **3개 이상이 수치·고유명사·예시로 구체화**됨 |

**채점 시 주의**
- ③은 이 문항에서 특히 중요하다. **"자료에 없는 수치는 만들지 말고 '자료 없음'으로 표기하라"** 류의 제약은 환각을 지시 단계에서 차단하는 것이므로 반드시 ③으로 인정한다.
- `ai_use_disclosure`로 첨부된 프롬프트가 있으면 그것을 근거로 함께 본다.
- 지시문을 여러 턴으로 나눠 설계했고 **다음 턴의 수렴 방향**(결과가 기대와 다를 때 무엇을 고칠지)까지 적었다면 5점 요건의 "구체화"로 인정한다.

## D3. 검증 설계 (5점) — 카운트형 ★주 변별 차원

| | 요소 | 인정 기준 |
|---|---|---|
| ① | 검증 대상 지정 | 어느 수치·어느 주장을 볼 것인지 특정 |
| ② | 검증 방법 | 원자료 대조 / 재계산 / 독립 재생성 후 비교 / 타인 리뷰 |
| ③ | 실패 시 행동 | 틀렸을 때 무엇을 하는지 |
| ④ | 검증 주체·시점 | 누가, 언제 |

| 점 | 기준 |
|---|---|
| **1** | "확인하겠다" 등 방법 없는 언급, 또는 없음 |
| **2** | 1개 요소 |
| **3** | 2개 요소 |
| **4** | 3개 요소, 방법이 **실행 가능한 수준**으로 기술됨 |
| **5** | 4개 전부 + **검증 비용을 의식한 우선순위**(무엇을 먼저 / 무엇은 안 볼지) |

**채점 시 주의 — 이 문항의 핵심 변별점**
- 페르소나 지문에는 **원자료에 존재하지 않는 항목을 AI가 채워 넣을 여지**가 설계되어 있다. 답안이 "투입한 자료에 없는 항목이 결과에 나왔는지"를 검증 대상으로 지목했다면 ①의 강한 충족으로 보고, 그 자체로 최소 3점을 준다.
- "전부 확인한다"는 5점이 아니다. 5점은 **안 볼 것을 정하는 판단**을 요구한다.

**상한**: 페르소나 항목명을 하나도 지목하지 않았으면 상한 3점.

---

## D4. 업무 전환 효과 (5점)

| 점 | 답안의 모습 |
|---|---|
| **1** | 효과 언급 없음, 또는 **무엇이 나아지는지 특정하지 않는다** ("효율화된다") |
| **2** | **시간·작업량 절감만** 말한다. 수치는 요구하지 않는다 |
| **3** | 사라지거나 줄어드는 **구체적 작업 단계를 이름으로** 지목했다 |
| **4** | 3 + 절감된 시간이 **무엇으로 전환되는지** 적었다 |
| **5** | 4 + **전파 경로**(문서화/템플릿/담당자)와 **성과 보고 지표** |

페르소나 상황이므로 "이 페르소나의 조직에서"라는 전제로 답해도 인정한다. 단 3점 이상은 페르소나 지문에 등장한 **실제 단계 이름**을 지목해야 한다.

**상한**: 페르소나 항목명을 하나도 지목하지 않았으면 상한 3점.

## 감점 적용

D1–D4 합계에 [penalty-risk.md](penalty-risk.md)의 감점을 적용한다. 하한 0점.

FR-02는 페르소나에 따라 **민감 데이터가 지문에 포함**되어 있다(예: 인사 페르소나의 평가 원천데이터, 영업 페르소나의 고객 연락처). 지시문이 그 데이터를 외부 도구에 그대로 투입하는 내용이면 감점 −5가 적용된다. 이것이 FR-02의 리스크 측정 장치다.

## 채점 기록 양식

[fr-01.md](fr-01.md)와 동일. `required_anchors` 칸 대신 **페르소나 항목명 지목**(`score.py --prompts`의 기계 판정)을 옮겨 적는다.

```
응답 id:                페르소나: HR / SALES / MFG / FIN / DEV / STAFF
D1 위임경계: _점 | 근거 인용: "..."
D2 구체성:   _점 | 카운트: ①②③④ = 4개 | 근거 인용: "..."
D3 검증설계: _점 | 카운트: ①②③ = 3개 | 근거 인용: "..."
D4 전환효과: _점 | 근거 인용: "..."
감점: _점 | 해당 규칙:
합계: _/20
페르소나 항목명 지목: `계정 과목`, `집행 금액` (score.py 판정: 상한 미적용)
지시문 실제 작성 여부: ✅
```
