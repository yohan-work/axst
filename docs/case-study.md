# 케이스 스터디 — AI와 함께 만든 AI 역량 진단

> **한 줄 요약**: 조직이 "AI 교육을 누구에게 어떻게 줄지" 정하게 하는 진단 도구를, 여러 AI 에이전트와 함께 설계·구현·검증했다. 그 과정에서 **AI가 낸 결과가 틀린 지점을 19번 찾아 고쳤고**, 다시 틀리지 않도록 검사로 고정했다.
>
> 바로 보기: [응시 체험](https://yohan-work.github.io/axst/) · [개인 리포트 샘플](https://yohan-work.github.io/axst/samples/report-individual.sample.html) · [조직 리포트 샘플](https://yohan-work.github.io/axst/samples/report-org.sample.html)

이 문서는 결과물 설명이 아니라 **일하는 방식**을 보여 주려는 기록이다. 도구 자체는 [README](../README.md)에 있다.

## 1. 문제 — 무엇을 풀려고 했나

AI 교육을 받은 직원의 82%가 현업에서 쓰지 못하고, 역량 진단 결과를 교육 설계에 실제로 반영한 조직은 **3.6%**다([출처](https://blog.bloomworld.ai/why-ai-training-doesnt-stick/)). 한편 2026년 하반기 공채부터 HD현대·기아·CJ올리브네트웍스가 **AI 활용 역량 평가를 채용에 넣기 시작했다**. 들어오는 사람의 AI 역량은 재기 시작했는데, **이미 일하고 있는 구성원을 어떻게 가르칠지는 여전히 감으로 정한다.**

그래서 풀 문제를 "좋은 시험 문항"이 아니라 **"진단 결과가 교육 결정으로 이어지게 하는 것"**으로 잡았다.

| 흔한 접근 | 이 프로젝트의 선택 | 이유 |
|---|---|---|
| 툴 지식 시험("다음 중 Claude 모델이 아닌 것은") | **툴 상식 문항 금지.** 상황 판단형 3유형만 허용 | 모델명은 6개월이면 바뀌고, 아는 것과 쓰는 것은 상관이 거의 없다 |
| 축별 점수·레이더 차트 | **축은 3단 신호만.** 총점도 ±5점 구간 | 축당 4문항으로는 2/4와 3/4가 통계적으로 구별되지 않는다. 숫자로 주면 거짓말이 된다 |
| 진단 후 리포트 전달 | **진단 전에 스폰서 합의문 1쪽**("이 결과로 바꿀 것 2개") | 리포트 한 장으로 끝나는 것이 이 문제의 실패 방식 그 자체다 |
| 교육용·인사평가용 겸용 | **겸용 금지** | 점수가 인사에 쓰이면 응시자가 점수를 방어하기 시작해 교육 설계 데이터가 오염된다 |

## 2. 무엇을 만들었나

```
스폰서 합의 → 응시(35분, 오프라인 HTML) → 객관식 자동 채점 → 주관식 LLM 5패스 채점 → 개인·조직 리포트 → 교육 처방·반 편성
```

- **문항 뱅크**: 5개 축(위임 판단력·작업 설계·검증·워크플로우 재설계·리스크) 객관식 24 + 주관식 2 + 직무 페르소나 6
- **채점**: 주관식은 차원마다 **독립된 LLM 대화**로 채점한다(한 번에 채점하면 차원 점수가 서로 끌려간다). 사람이 20%를 다시 채점해 2점 이상 어긋나면 사람 판정을 따른다
- **운영 도구**: `pilot.py` 한 명령으로 응답 점검 → 채점 → 리포트 → 삭제. Python 표준 라이브러리만 쓴다(사내 PC에서 설치 없이 돈다)
- **안전장치**: 리포트에 "정답"·축별 숫자·백분위가 들어가거나 5명 미만 칸이 가려지지 않으면 **파일을 쓰지 않는다**. 테스트 91개와 CI

## 3. 어떻게 일했나 — 사람과 AI의 역할 분담

| 누가 | 한 일 |
|---|---|
| **나** | 풀 문제와 원칙 정의, 설계 결정(아래 §5), 결과물 검토·승인, 공개 범위·라이선스 같은 되돌리기 어려운 결정 |
| **Claude Code (Opus)** | 설계 문서·문항·도구 구현, 검증 회차 설계, 자기 산출물 재검토 |
| **Claude (Sonnet)** | **다른 모델로 교차 채점** — Opus가 쓴 앵커 답안을 Sonnet이 점수를 모른 채 채점 |
| **Codex CLI** | 인계 문서(`AGENTS.md`)를 받아 버그 수정을 넘겨받음. 결과는 다른 에이전트가 리뷰 후 병합 |
| **합성 응시자 10명 (LLM)** | 직무·수준·오개념을 부여받아 실제로 응시 → 문항이 의도대로 오답을 끌어내는지 확인 |

작업을 나눌 때 기준은 이 진단의 1축과 같다 — **책임이 걸린 판단인가, 되돌릴 수 있는가.** 구현은 맡기고, 되돌리기 어려운 결정(저장소 공개 유지, 파일럿 참여자에게 리포트를 줄지)은 사람이 쥐었다.

## 4. AI가 틀린 것을 잡은 기록

이 프로젝트에서 가장 많이 배운 부분이다. **"통과"라는 표시를 믿지 않는 습관**이 여기서 만들어졌다.

### ① 린트는 PASS였는데, 그 검사가 없었다
정답지의 정답을 일부러 바꿔 봤는데 린트가 통과했다. 정답이 어긋나면 그 문항은 응시자 전원이 오채점되는데, 그걸 막는 검사가 아예 없었던 것이다. → 응시본의 모든 파생값을 원본 문항과 전수 대조하는 검사를 넣었고, **"검사를 추가하면 대상을 고의로 깨뜨려 FAIL을 확인한다"**를 규칙으로 만들었다. 이후 추가한 모든 검사는 이 방식으로 확인했다.

### ② 존재하지 않는 결함 2건을 보고했다가 철회했다
측정 스크립트가 섹션을 못 찾자 파일 전체로 조용히 대체했고, 글자 수가 2배로 부풀어 "지문이 상한을 넘는다"는 가짜 결함이 나왔다. → 보고를 공개적으로 철회하고 **"못 찾으면 대체하지 말고 실패한다"**를 규칙으로 만들었다. 리포트 생성기는 정본 문서의 표를 못 읽으면 추측하지 않고 멈춘다.

### ③ 통과 조건이 가장 쉬운 차원 하나만 보고 있었다
채점 리허설의 통과 조건이 네 차원 중 D1만 검사해서, **나머지 차원의 앵커 오류 5건이 "통과"에 가려졌다.** → 통과 조건을 네 차원 전부 ±1로 바꿨다. 그 뒤 **채점 모델을 바꿔(Opus → Sonnet)** 다시 돌렸고 60개 점수 중 46개가 일치, ±2 이상 불일치 0건이었다.

### ④ 질문이 채점 기준을 알려 주고 있었다
합성 응시자 10명의 주관식을 보니 검증 설계(D3) 5점이 21번에서는 0명, 22번에서는 7명이었다. 원인을 추적하니 22번 질문이 5점 조건을 그대로 묻고 있었다. 주관식이 역량이 아니라 **"질문을 따라 쓰는 능력"**을 재고 있던 것이다. → "질문은 4점 요건까지만 묻는다"는 원칙을 세우고 질문을 고쳤다.

### ⑤ 에이전트의 자기 보고는 틀렸다
합성 응시자 하나가 "개인정보를 마스킹 없이 넣는 위반을 답안에 심었다"고 보고했지만, 감점 채점이 원문을 읽어 보니 그런 문장이 없었다. → **에이전트가 스스로 한 말은 근거로 쓰지 않는다. 원문을 읽는 절차만이 근거다.**

### ⑥ 응시자 리포트에 "정답"이 샐 뻔했다
L4 응시자에게 "전파 역할"을 안내하는 문구가 설계 문서에서 그대로 옮겨지면서 `(MC-FLW-003 정답 구조)`라는 내부 참조를 달고 나올 뻔했다. 리포트 생성기의 금지 표현 검사가 파일을 쓰기 전에 잡았다. → 응시자용 문구에서 문항 id 참조를 걸러 낸다.

## 5. 내가 내린 결정과 버린 안

| 결정 | 물음 | 버린 안 |
|---|---|---|
| **공개 저장소를 유지하고, 공개된 폼 A는 점수가 나가는 진단에 쓰지 않는다** | 정답이 공개된 시험을 어디까지 쓸 수 있나? | 비공개 전환 — 방법론 공유라는 목적을 버린다 |
| **파일럿 참여자에게 참고용 개인 리포트를 준다**(조건 3개) | 점수를 안 알려주는 게 폼 A를 쓸 근거였는데, 리포트를 주면? | 리포트 없음 — 참여 동기와 제안 근거가 사라진다 |
| **소규모 조직 리포트는 레벨을 2구간으로 묶는다** | 12명에서 5명 미만 칸을 가리면 표가 비는데? | 가림 기준 완화 — 익명성을 판다 |
| **주관식은 사내 허용 LLM에 붙여넣기, API 자동화는 하지 않는다** | 답안에 사내 시스템명이 들어가는데 외부 API로 보내도 되나? | API 자동 채점 — 편하지만 조직 데이터 정책을 넘는다 |
| **코드 MIT, 콘텐츠 CC BY 4.0** | 누가 가져다 쓰게 할 것인가? | 비상업 한정 — 확산이 목적인데 장벽이 된다 |
| **채용용으로 설계하지 않는다** | 채용 시장이 이 역량을 보기 시작했는데 채용용으로 넓히면? | 겸용 — 측정 목적이 섞이면 데이터가 오염된다(§1) |

## 7. 아직 모르는 것

## 8. 직무별로 보면

- **AX 컨설팅** — 문제를 "문항"이 아니라 "결과가 결정으로 이어지지 않는 것"으로 다시 정의했다(§1). 진단 전에 스폰서 합의문을 받는 구조, 교육으로 안 풀리는 것(권한·양식·데이터 등급표)을 따로 처방하는 [처방 문서](06-prescription.md), 결정권자용 [1쪽 제안서](13-pilot-proposal.md)
- **AX 기획** — 측정이 감당할 수 있는 만큼만 보고하는 설계(§1), 결과를 보기 전에 판단 기준을 정한 관문 B(§7), 파일럿 → 본 시행 → 재진단으로 이어지는 [운영 절차](14-pilot-runbook.md)와 개인정보 취급 규칙
- **AX 개발** — 여러 모델을 역할별로 나눠 쓰고 교차 검증한 운영(§3), LLM 출력을 기계 판독 블록으로 받아 검증하고 통과할 때만 반영하는 파이프라인, "고의로 깨뜨려 확인"하는 테스트 문화(§4), 의존성 없는 도구와 CI
