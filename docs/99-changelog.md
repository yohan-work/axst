## 2026-09-16 — 2단 채점 리허설 (회차 C0)

문항 수정 없음. 검증 실행과 결함 기록만 추가했다.

### 실행한 것

[07-validity-plan.md](07-validity-plan.md) 2단의 채점 리허설. 앵커 12개(FR-01 6 + FR-02 6)와 페이킹 시험 답안 2개를 [llm-scorer-prompt.md](../rubrics/llm-scorer-prompt.md) 프로토콜(차원별 독립 4패스 + 감점 1패스)로 채점했다.

독립성 확보를 위해 패스마다 별도 컨텍스트를 쓰고, 배치 순서를 섞고, 레벨 라벨·부여 점수·출제자 볼드 강조를 제거하고, 루브릭 외 파일 접근을 차단했다. **그래도 앵커를 쓴 것과 같은 모델 계열이 채점했으므로 독립 검증이 아니다** — 일치는 타당도의 증거가 아니고 불일치만 신호다.

### 결과

| 통과 조건 | 판정 |
|---|---|
| D1 차이 전부 ±1 이내 | 통과 (12개 중 10개 일치, 2개 −1) |

### 수정하지 않은 것 (의도적)

결함 10건을 전부 미수정으로 남겼다. 둘은 설계 판단이 필요하다.

- **갈래 A** — FIN 페르소나에서 감점 −5가 과잉 발동한다. 앵커 부여값(0)과 규칙(−5)이 모순이고, FIN 선택자 3명 중 2명이 감점을 받았다. 감점 발생률이 조직 리포트의 RSK 보조 지표인데 **페르소나 선택에 오염된다**. 앵커를 고칠지 규칙 범위를 좁힐지 결정이 필요하다
- **갈래 B** — 페이킹 방어가 D2·D4에만 있어서, 업무 내용이 한 글자도 없는 답안이 FR-01에서 14/20을 받는다. D1·D3에도 상한을 걸지 결정이 필요하다

나머지 8건(앵커 부여값 정정 5건, 프로토콜·문서 문구 3건)은 갈래 결정 후 일괄 반영한다.

### 추가 — 시간 예산 정합성 검사

소요 시간 실측은 사람 몫이므로, 대신 각 문항의 `time_sec` 배정이 실제 글자 부피와 맞는지 기계적으로 검사했다. 결함 3건을 더 찾았다(11~13).

가장 큰 것은 **공통 지문 4개가 전부 200자 상한을 초과**하는데(230~306자, 최대 +53%) 린트가 공통 지문 길이를 아예 검사하지 않는다는 것이다. 상한이 문서에만 있고 기계에는 없었다. 린트에 검사를 추가하면 현재 상태가 즉시 FAIL이 되므로, 상한을 고칠지 지문을 고칠지 결정 전에는 추가하지 않는다.

전체 추정은 34~40분으로, 하한은 목표(35분 ±3분) 안이지만 상한이 벗어난다.
