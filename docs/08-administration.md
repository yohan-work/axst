## 사전 안내자료 (응시자에게 미리 배포)

응시 최소 1일 전에 배포한다. 우선순위 규칙을 공개하지 않으면 이 진단은 독심술 시험이 된다.

### 이 진단이 무엇인지

- 조직의 AI 활용 역량을 진단해 **교육을 수준별로 설계하기 위한 자료**입니다.
- **툴 지식을 묻지 않습니다.** 모델 이름, 기능 명칭, 용어 정의는 나오지 않습니다.
- 대신 실제 업무 상황에서 **어떻게 판단하는지**를 봅니다.

### 결과가 어디에 쓰이는지

> 이 진단의 결과는 교육 설계에만 사용되며, 인사 평가·승진·배치 자료로 사용되지 않습니다.

*(ⓑ 인증 회차인 경우 이 문장을 쓰지 않고 실제 용도를 명시한다)*

### 이 진단이 쓰는 우선순위 규칙 ★

일부 문항은 "가장 먼저 할 일"을 묻습니다. **모든 선택지가 옳을 수 있고, 그중 우선순위를 봅니다.** 이 진단이 사용하는 규칙은 다음 세 가지입니다.

| | 규칙 |
|---|---|
| **검증 우선순위** | `의사결정에 직접 쓰이는가 × 원자료로 재현 가능한가`. 두 조건이 비슷하면 **"없다고 한 것"을 "있다고 한 것"보다 먼저** 봅니다 — 없다고 한 것은 확인하지 않으면 드러나지 않기 때문입니다 |
| **위임 경계 기준** | 작업량이 아니라 `책임이 귀속되는 판단인가 × 되돌릴 수 있는가` |
| **흐름 개선 우선순위** | 단계를 덧붙이는 것보다 **없앨 수 있는 단계**가 먼저 |

### 문항 구성

| 부 | 내용 | 시간 |
|---|---|---|
| 0부 | 자기보고 3문항 (**점수 미반영**) | 2분 |
| 1부 | 객관식 20문항 (문항당 3점). 4·13·17·18번은 **가장 적절한 것과 가장 부적절한 것을 각각** 고름 | 20분 |
| 2부 | 주관식 2문항 (문항당 20점) | 13분 |

### 주관식 준비 사항

- **21번**은 본인이 지난 한 달 안에 실제로 수행한 반복 업무 1개를 대상으로 답합니다. 미리 하나를 정해 두시면 좋습니다. 답안에 **업무 이름 / 사용하는 시스템 이름 / 데이터 항목 이름**이 들어가야 합니다.
- **22번**은 6개 직무 페르소나 중 본인 직무에 가까운 것을 골라 답합니다.
- **AI를 사용해 답안을 작성해도 됩니다.** 사용한 경우 **사용한 프롬프트를 답안 끝에 첨부**해 주십시오. 첨부한 프롬프트는 채점 자료로 함께 사용됩니다.

## 시행

### 지필 / 온라인

| | 지필 | 온라인 |
|---|---|---|
| 자료 | `forms/form-A.md` 인쇄 + 페르소나 별지 6장 | `forms/form-A.web.html` (아티팩트로 게시) |
| 페르소나 | 별지 6장 | 선택하면 해당 지문이 펼쳐짐 |
| 타임박스 | 감독자가 구두 안내 | 구간별 잔여 시간 표시 (**강제 종료하지 않음**) |
| 응답 회수 | 응답지 수거 | 응시자가 JSON을 파일 저장 또는 복사해 담당자에게 전달 |
| 소요 시간 기록 | 수기 | **구간별·문항별 자동 기록** |

**온라인 응시본은 응답을 서버에 저장하지 않는다.** 응답은 응시자 브라우저 안에만 있고, 제출 화면에서 본인이 내보내야 담당자에게 도달한다. 무기명 약속을 지키기 위한 설계이고, 대가로 **회수가 자동이 아니다** — 미제출자를 담당자가 직접 확인해야 한다.

**온라인 응시본에도 정답이 없다.** 자동 채점을 붙이면 정답이 브라우저로 내려가 개발자 도구로 읽힌다. 채점은 응답을 받아 오프라인에서 한다.

| 항목 | 규칙 |
|---|---|
| 방식 | 동일 시간대 일괄 시행 (구두 전파 방지) |
| 타임박스 | 35분. 0부 2분 → 1부 20분 → 2부 13분 안내 |
| 자료 | 지필: 응시본 + 페르소나 별지 6장 / 온라인: 게시 링크 |
| 식별 | ⓐ 진단 회차는 무기명 또는 가명. 가명은 재진단 대조를 위해 본인만 아는 규칙으로 생성하게 한다 |
| 감독 | 타임박스를 안내하되 강제하지 않는다. 지필에서 검색 차단은 불가능하고, 주관식은 `required_anchors`로 방어된다 |
| 미제출 처리 | 주관식 미작성은 0점으로 처리하되, **미작성률이 20%를 넘으면 시간 배분을 재검토**한다 |

### 응시 중 질문 대응

| 질문 | 답 |
|---|---|
| "정답이 여러 개인 것 같다" | "모든 선택지가 옳을 수 있습니다. 우선순위 규칙을 참고해 주십시오." |
| "우리 회사 규정을 기준으로 답해야 하나" | "네, 본인 조직의 규정을 기준으로 답해 주십시오." |
| "AI를 써도 되나" | "주관식은 사용하셔도 됩니다. 사용한 프롬프트를 첨부해 주십시오. 객관식은 사용하지 마십시오." |
| "인사에 반영되나" | ⓐ 회차: "반영되지 않습니다." ⓑ 회차: 실제 용도를 그대로 답한다 |

## 폼 분리: 공개 참조 폼과 시행 폼

**이 저장소는 공개다.** 문항 파일은 SSOT를 유지하려고 정답·해설·오답 진단을 함께 들고 있으므로, 그것들도 공개다. 따라서 —

> **폼 A로는 점수가 나가는 진단 회차를 시행하지 않는다.**

응시자가 검색으로 정답지에 닿을 수 있으면, 그 점수는 역량이 아니라 **검색 여부**를 잰다.

| | 공개 참조 폼 (폼 A) | 시행 폼 (폼 B 이후) |
|---|---|---|
| 저장소 | 공개 | **비공개** |
| 정답 접근 | 누구나 | 채점자만 |
| 용도 | 방법 참조 · 교육 · 설계 검토 · **문항 분석 파일럿** | 점수가 나가는 진단 회차 |
| `visibility` | `공개참조` | `비공개시행` |
| `exposures` | **0을 유지한다** (린트가 검사) | 회차마다 +1 |

**파일럿은 폼 A로 해도 된다.** 파일럿의 목적은 사람을 진단하는 것이 아니라 **문항을 진단하는 것**(정답률·변별도·오답 선택률)이고, 응시자에게 점수가 통보되지 않으므로 정답을 찾아볼 유인이 약하다. 다만 사전 안내에 **"이 폼의 정답은 공개되어 있으며, 찾아보면 문항 분석이 무의미해진다"**를 명시한다. 파일럿을 돌려도 `exposures`는 올리지 않는다 — 시행이 아니기 때문이다.

### 시행 폼을 만드는 절차

1. 비공개 저장소를 만든다
2. 이 저장소의 `items/` 구조·[출제 규칙](03-item-writing-rules.md)·[배분표](02-blueprint.md)를 그대로 쓰고 **문항만 새로 출제**한다. 방법은 공개, 문항은 비공개다
3. `MANIFEST.yml`에 `visibility: 비공개시행`
4. 린트·채점·리포트·처방 문서는 이 저장소 것을 그대로 참조한다

| 대상 | 조치 |
|---|---|
| 정답·해설 | 문항 파일에 남기되(SSOT 유지) **응시본 빌드 단계에서 제거**. 응시본에는 정답 필드가 물리적으로 없다 |
| 정답지 | `forms/form-A.answers.md`는 채점자 전용. 공개 참조 폼이라 이미 공개되어 있다 |
| 노출 관리 | 시행 폼만 `stats.exposures` 기록. 2회 노출 후 폼 교체 |
| 팀 내 전파 | 동일 시간대 일괄 시행. 폼이 둘 이상이면 코호트별 교대 운영 |

## 시행하지 않아야 하는 경우

아래 중 하나라도 해당하면 **시행을 보류하고 스폰서에게 되돌린다.**

- 스폰서 합의문에 §1(바꿀 것 2개) 또는 §3(책임자 실명)이 비어 있다
- 한 회차에서 교육 설계와 인사 평가를 겸하려 한다
- 축별 점수나 순위표를 요구받았고, 그것이 제공되지 않는다는 점을 스폰서가 수용하지 않는다
- 응시 인원이 10명 미만인데 조직 리포트를 요구받았다
- 출구 전략 체크리스트의 "흐름을 바꿀 수 있는가" 3항목이 전부 미충족인데 FLW 축 처방을 요구받았다
