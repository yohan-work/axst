# 11. 합성 파일럿 — 회차 S0

LLM 에이전트 10명에게 서로 다른 직무·AI 활용 수준·오개념을 부여하고 폼 A를 실제로 풀게 한 기록.

**일자**: 2026-09-16 · **응시자**: 합성 10명 · **채점**: `scripts/score.py` + 감점 패스 1회

---

## ⚠️ 이 데이터를 무엇에 쓸 수 있고 무엇에 쓸 수 없나

> **이것은 실제 파일럿이 아니다. 여기의 `p`(정답률)를 근거로 문항을 폐기하지 마라.**

응시자 10명 중 6명에게 **특정 축의 오개념을 의도적으로 심었다.** 따라서 이 표본은 모집단을 대표하지 않고, 정답률은 문항 난이도가 아니라 **표본 설계**를 반영한다.

| 지표 | 쓸 수 있나 | 이유 |
|---|---|---|
| 오답 선택률 패턴 | ✅ | 어떤 오답이 어떤 오개념을 끌어당기는지 보인다 |
| 오개념 → 오답 적중 | ✅ | 설계 의도가 실제로 작동하는지 직접 검증된다 |
| 모호 문항 지목 | ✅ | 상·하위가 같이 헷갈린 문항은 문항 쪽 문제다 |
| 감점 규칙 작동 | ✅ | 같은 페르소나 안에서 행동에 따라 갈리는지 보인다 |
| 축 분리 | ✅ | 축 프로파일이 부여한 강·약점과 일치하는지 보인다 |
| **정답률 `p`** | ❌ | 표본을 내가 만들었다. 난이도 추정이 아니다 |
| **변별도 `d`** | ⚠️ | 역할극 수준은 실제 역량이 아니다. **부호만** 참고 |
| **소요 시간** | ❌ | 에이전트의 읽기 시간은 사람과 무관하다 |

**역할극이 실제 저역량자보다 강하다.** 하위 2명이 4/60·5/60으로 무작위 기대값(15/60)보다 낮았다. 실제 사람은 이렇게 일관되게 함정만 고르지 않는다. 오답의 매력도는 검증됐지만 정답률은 과소 추정이다.

## 방법

1. `forms/form-A.md` + 페르소나 별지를 합쳐 **정답이 없는 응시 패킷**을 만들었다 (`정답`·`해설`·`distractor` 문자열 부재를 기계 검사)
2. 에이전트 10명에게 각각 **직무 / AI 활용 수준 / 가진 오개념**을 부여하고, 패킷 외 파일 접근을 차단한 뒤 풀게 했다
3. **모델을 전원 동일하게(Sonnet) 고정했다.** 모델 강도가 섞이면 수준 조작이 아니라 모델 차이를 재게 된다
4. 응답을 `schema: axst-response-1` JSON으로 받아 `scripts/score.py`로 채점했다
5. 주관식은 `--prompts`로 패킷을 만들어 **감점 패스만** 독립 컨텍스트에서 돌렸다

원시 응답은 커밋하지 않는다(`pilot/responses/` 규칙과 동일하게 취급). 아래 집계표가 보존 대상이다.

## 검증된 것

### 1. 오답이 오개념을 낚는다 — 18개 대조 중 15개 적중

부여한 오개념이 **그 오개념을 진단하도록 설계된 오답**으로 갔는지 확인했다.

| 문항·선택지 | 진단 대상 | 결과 |
|---|---|---|
| 1번 ③ · 13번 ③ | **겉보기 human-in-the-loop** | ✅ `BE`·`PM-junior`가 **두 문항 모두** 정확히 선택 |
| 19번 ① | 사번은 식별자가 아니라는 오해 | ✅ `FE`·`MKT` 정확히 |
| 16번 ① | 출처 형식이 있으면 실재한다는 오해 | ✅ 부여 2명 + 예상 외 3명 |
| 2번 ① | 역할 부여 신화 | ✅ 부여 2명 + 예상 외 3명 |
| 20번 ② | 사실 검증하면 고지 의무 면제라는 오해 | ✅ 부여 1명 + 예상 외 4명 |
| 1번 ④ · 9번 ① · 18번 ① | AI 회피 · 덧붙이기 · 시간 절감만 | ◐ 일부만 |

**겉보기 HITL 적중이 가장 중요하다.** 이 개념은 주관식 D1 상한의 근거이고 회차 C0에서 앵커 오류를 낳았던 지점인데, **객관식 두 문항이 같은 두 사람을 독립적으로 잡아냈다.** `distractor_dx`가 장식이 아니라 실제 처방을 가리킨다는 증거다.

### 2. 축이 서로 다른 것을 재고 있다

부여한 강·약점이 축 프로파일에 그대로 찍혔다.

| 응시자 | 축 프로파일 | 부여한 설정 |
|---|---|---|
| `DATA` | DEL 4/4 · DSN 4/4 · **FLW 0/4** | "혼자 최적화, 전파 무관심" |
| `BE` | DSN 4/4 · **DEL 1/4** | 겉보기 HITL |
| `FE` | DSN 4/4 · **RSK 0/4** | "코드는 잘하고 규정엔 둔감" |
| `HR` | 전 축 낮음 · **RSK 4/4** | "개인정보엔 강하다" |

축이 한 덩어리로 움직였다면 축 분리가 실패한 것이다. **개별 축이 부여한 설정대로 따로 무너졌다.**

### 3. 감점 규칙이 페르소나가 아니라 행동으로 갈린다

감점 발생: **20개 답안 중 2개(10%)**, 둘 다 −5.

| 응답 | 판정 | 근거 |
|---|---|---|
| `DESIGN` 22번 | **−5** | 지문이 경고한 `반려 사유 코드`(개인 사유 포함)를 지시문에 마스킹 없이 포함 |
| `MKT` 22번 | **−5** | 지문이 경고한 거래처 담당자 이름·연락처를 그대로 투입 |

**같은 페르소나를 받고도 갈렸다.** STAFF 페르소나 3명 중 `PM-senior`·`PM-junior`는 **지시문 단계에서 사전 마스킹**을 명시해 0점, `DESIGN`은 사후에 *"그냥 빼달라고 하고 넘어갈 것 같아요"* 라고만 해 −5를 받았다. SALES 페르소나도 `SALES`는 0, `MKT`는 −5로 갈렸다.

> 이것은 [10-calibration-findings.md](10-calibration-findings.md) **결함 16**(FIN 페르소나 감점 편향)에 대한 반대 증거다. 감점 규칙이 페르소나 조건만으로 기계적으로 발동하는 것이 아니라, **응답자가 실제로 무엇을 하겠다고 썼는지**로 갈릴 수 있음을 보여준다. 다만 이 회차에는 FIN 응답이 1개(`OPS`)뿐이었고 그마저 "사내 도구 외에는 넣지 않는다"고 명시해 0이었으므로, **결함 16이 해소된 것은 아니다.**

우선순위 규칙을 사전 안내에 공개했는데도 적용이 갈린다면, 문제는 응시자가 아니라 **규칙 문장이나 선택지 설계**다.

### 주관식이 드러낸 것

1. **D3가 문항에 따라 갈린다 — 22번 질문이 5점 요건을 노출한다.** 22번 ③은 *"무엇을 먼저 보고 무엇은 보지 않겠습니까?"* 라고 묻는데, 이것이 D3 5점 요건(검증 비용 우선순위) 그 자체다. 21번 ③은 이를 묻지 않고, **21번 D3 5점은 0명, 22번은 7명**이다. 객관식 VER 축 평균 정답률이 25%로 낮은데 주관식 D3가 높은 어긋남의 유력한 원인이다 — **주관식이 역량이 아니라 질문을 따라 쓰는 능력을 재고 있을 수 있다.**
2. **D2 요소 ⑤(톤/품질 기준·예시)를 받은 답안이 20개 중 0개다.** 형용사("심플하게", "친근하고 트렌디하게")는 전부 불인정됐다. **D2 5점 칸이 실질적으로 도달 불가능하다.** 회차 C0의 결함 2(만점 앵커가 ⑤ 없이 4점)가 앵커만의 문제가 아니었다.
3. **페이킹 방어 상한이 80개 차원 점수에서 한 번도 발동하지 않았다.** 모든 응시자가 업무명·시스템명·데이터 항목명이나 페르소나 조건을 최소 하나는 썼다. 네 차원 상한(갈래 B)은 **인위적 시험 답안에서만 검증됐고 실제 작성물에서는 시험되지 않았다.**
4. **겉보기 HITL이 객관식과 주관식에서 수렴했다.** 객관식 DEL을 무너뜨린 `BE`·`PM-junior`는 주관식 D1도 2~3점이었고, 채점자가 두 사람 답안에서 "AI가 뽑은 후보 중 선택" 구조를 독립적으로 짚었다.
5. **±5 밴드 규칙을 적용하면 10명 중 5명이 레벨 경계다.** 레벨 4단계가 개인 단위에서는 거칠다는 뜻이고, 코호트 단위 해석 원칙(`docs/04`)을 뒷받침한다.
6. **`scripts/score.py`의 경계 표기 버그.** 위 표의 경계 판정은 손으로 했다. 채점기는 총점이 경계값과 **정확히 같을 때만** 경계로 표시해서(`level_of`의 `abs(total - b) <= 0`) 이 5명을 하나도 경계로 표시하지 않았다.

## 알려진 오류

작성 과정에서 **에이전트의 자기 보고를 원문 확인 없이 인용한 오류**가 있었다. `FE` 에이전트가 "고객 문의 원문을 마스킹 없이 투입했다"고 보고했으나, 감점 패스가 실제 답안을 읽고 **그런 서술이 없다**고 판정했다(0점). 에이전트의 자기 보고는 근거가 아니다 — **원문을 읽는 패스만이 근거다.**

## 재현

```bash
# 1. 정답 없는 응시 패킷 생성 (forms/form-A.md + 페르소나 별지)
# 2. 에이전트 10명에게 직무·수준·오개념을 부여해 풀게 함 (모델 고정)
# 3. 응답 JSON 수집 후
python3 scripts/score.py <응답들>.json --prompts out/
```

페르소나 정의는 위 [응시자 설계](#응시자-설계) 표가 전부다. 같은 설정으로 다시 돌리면 비교 가능하다.

## 이 회차가 대체하지 못하는 것

**실제 파일럿 10~15명은 여전히 필요하다.** 이 회차는 문항이 *의도한 오개념을 잡는지*를 확인했을 뿐, 실제 사람이 그 오개념을 얼마나 갖고 있는지는 말해주지 않는다. 정답률·변별도·소요 시간은 사람에게서 다시 재야 한다.
